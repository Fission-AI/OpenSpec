## Evidence and design choices

**Observed in current released-project documentation and GitHub default-branch source docs (checked 2026-11-09):** `openspec init` creates `openspec/config.yaml` and chosen agent integrations; the default core profile includes `propose`, `explore`, `apply`, `update`, `sync`, and `archive`; `propose` produces artifacts ready for `apply`; `archive` can sync delta specs; `config.yaml` supports `schema`, `context`, and per-artifact `rules`. Codex uses skill invocation (`$openspec-propose`), and Claude Code commonly uses `/opsx:propose`. OpenSpec documents that instruction rules and operation guidance are not enforcement. Sources: [setup](https://github.com/Fission-AI/OpenSpec/blob/main/docs-lab/start/setup.md), [commands](https://github.com/Fission-AI/OpenSpec/blob/main/docs/commands.md), [customization](https://github.com/Fission-AI/OpenSpec/blob/main/docs/customization.md), [supported tools](https://github.com/Fission-AI/OpenSpec/blob/main/docs/supported-tools.md), [FAQ](https://github.com/Fission-AI/OpenSpec/blob/main/docs/faq.md).

**External comparison:** GitHub Spec Kit introduces a project-level constitution and many sequential spec/planning steps. This demonstrates a team-governance surface, but the initial OpenSpec trial should **not** require teams to author a constitution or select a workflow architecture. Sources: [Spec Kit README](https://github.com/github/spec-kit), [constitution reference](https://github.com/github/spec-kit/blob/main/docs/reference/agentic-sdd.md). This is a design comparison, not proof that one onboarding method performs better.

**Team-adoption evidence:** No verified independent interviews or outcome data were available in this run; GitHub documentation and public issues are product-source evidence, **not** observed team trial outcomes. We should not interpret an example handoff as an observed user success. The import case and the two teammate names in the kit are **illustrative**, not a real customer's behavior.

## Verification performed and limitations

- Read current repository documentation and inspected actual `src/core/init.ts`, `src/core/config.ts`, and `openspec/specs/config-loading/spec.md` through the connected GitHub repository, plus public current docs, including workflow and configuration details. Distinguish **core/default** from expanded-only `verify` and `onboard` workflows. The kit does not rely on those optional commands.
- Inspected the configuration shape (`schema`, `context`, `rules.proposal`, `rules.specs`) against the repository's documented project config. Parsed the exact sample as YAML locally and checked its `schema`, `context`, and `rules` shape against the repository config-loading specification; this confirms **syntax and documented shape**, not the published CLI's runtime behavior.
- Walked the instructions for *two roles* and a fresh-agent handoff at the document level. The handoff, review dialogue and resulting delta spec are examples, **not an agent-executed or human-validated trial**.
- **Not verified:** actual npm package install / command execution in an OpenSpec-enabled test repo, agent workflow behavior across tools, mixed-tool setup, effectiveness of team review, or any adoption/productivity impact. The execution environment could not reach the npm registry for a live CLI test; do not imply release binary validation.
- **Version caution:** docs were inspected on the default branch as of 2026-11-09 and may describe unreleased changes. Before distributing widely, test the latest published CLI with a clean clone and confirm command availability and config behavior. Prefer a pinned verified version in an official kit once tested.

## Recommended first real test

Recruit **three teams without OpenSpec champions**, each with one author and one reviewer, and have them follow only `START-HERE-team-trial.md`. Watch their actual setup and first plan review; do not explain the workflow for them. Ask the second person to continue from a fresh conversation. Record blockers, plan revisions and the Friday decision. A single failed handoff should outweigh dozens of clicks on an onboarding page.
