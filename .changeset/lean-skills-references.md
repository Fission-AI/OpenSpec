New, opt-in `openspec-beta` skills, installed once per machine with `openspec setup`. One `openspec-beta` router skill says what OpenSpec is, the principles every skill follows, and when to read each skill's steps (`references/<skill>.md`) or a short guide (sizing a change, naming capabilities, decisions to raise, writing a requirement, how specs change); a short `openspec-beta-<skill>` skill keeps autocomplete (`/openspec-beta-propose`, or `/openspec-beta:propose` in Claude Code). Sync is no longer its own skill: apply's last task and archive merge the specs. Setup installs a Claude Code plugin and `~/.agents/skills` for Codex, Cursor, Gemini CLI, OpenCode, and others, moves older OpenSpec skills and `/opsx` command files into a backup, and `openspec setup --revert` puts everything back. Explore keeps a living draft; propose plans from the settled scope, checks what the code already does, and ends `tasks.md` with a spec update. Archive lets `openspec archive` merge and validate. `openspec context --json` now includes `project_context`. `openspec init --tools` still installs per-project skills under today's names, and their text is unchanged: `init` and `update` write byte for byte what the previous release wrote, so an existing project sees nothing new until someone opts in. The `skills/` folder that `npx skills add` installs now holds the beta set instead of those names, so a previous `npx skills add` leaves its copies in place; `skills/README.md` has the command that removes them.
